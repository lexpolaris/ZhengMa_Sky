## 1. 总体设计思路

### 1.1 设计目标

原版是一款**自学型打字训练软件**，其设计目标可从功能反推：

- **无需输入法**：训练时用户只需在输入框输入编码字符串，程序自行判定对错，不依赖系统安装郑码输入法。
- **数据可扩展**：以"单元"为单位组织学习内容（从笔画、字根到词、常用字），课程体系完整。
- **进度可追踪**：记录每题的反应速度，动态判断"哪些内容还不熟"。
- **训练/测试双轨**：训练用于学习，测试用于检验并记录成绩曲线。
- **单机、单用户、离线**：数据保存在本地文件，注册表保存少量配置。

### 1.2 核心设计思想：**"末位训练"（Tail Training）**

这是原版最核心、也是最具创新性的教学理念：**让练习始终集中在用户最不熟练的题目上**。

设计推导：

1. 为每道题维护一个 **速度值**（即用户的反应时间，单位 ms）。反应越慢 → 速度值越大。
2. 每一轮训练时，按速度值**从慢到快排序**，只抽取最慢的若干题做本轮题目。
3. 抽出的题目再**随机洗牌**，避免顺序固定导致记忆位置而非记忆内容。
4. 答对 → 速度值变小；答错 → 打成极大错误标记，下轮必中。
5. 随着训练，"末位"的范围不断滑动，整体水平被持续向上"抬升"。

**设计意图**：传统打字练习随机出题，用户大量时间浪费在已熟练的题目上。末位训练把有限的时间集中到"最薄弱点"，效率更高。这一思想贯穿训练模式、测试模式与单元完成判定（`Used`）——**速度表是贯穿全局的唯一核心状态**。

### 1.3 学习环节划分

原版把学习内容划分为**单元（Lib）**，每个单元提供两个环节：

| 环节 | 计时方式 | 出题策略 | 目的 |
|------|----------|----------|------|
| 训练 | **有效计时**（离开不计时） | 末位训练，多轮循环 | 学习、攻克薄弱点 |
| 测试 | **秒表计时**（无条件累计） | 覆盖性出题，记录成绩 | 检验水平、看进步曲线 |

原版刻意让"训练"与"测试"相辅相成：越熟练，越应以测代练。

## 2. 原版架构剖析

### 2.1 技术栈

| 项目 | 原版选择 |
|------|----------|
| 语言 | C++（Object Pascal 风格的 VCL 封装） |
| 框架 | Borland C++ Builder / VCL |
| 界面 | 原生 Win32 控件（TForm / TLabel / TEdit / TRichEdit 等） |
| 图表 | TeeChart（Borland 自带） |
| 数据 | 二进制/自定义格式 + 加密（LCG + XOR） |
| 配置 | Windows 注册表 |
| 字体 | 自带字根字体（zmzg.ttf） |

### 2.2 模块划分

原版是一个**单窗体（MainForm）+ 若干对话框**的典型 VCL 程序，逻辑集中在主窗体的方法中：

```
MainForm（主窗体）
 ├─ 题目区：显示当前字/词、拆分提示、联想提示、输入框
 ├─ 信息区：单元名、等级、速度、正确率、进度、查码框
 ├─ 状态栏：单元名、模式、时钟
 └─ 对话框：
      ├─ 选单元（UnitSelect）
      ├─ 参数设置（Setup）
      ├─ 测试成绩（TestResult，TeeChart 曲线）
      └─ 帮助（Help，TRichEdit）

数据侧：
 ├─ 题库（单元/题目）
 ├─ 用户档（进度 + 速度表 + 等级/积分/连对）
 ├─ 码表（zmmb）
 └─ 测试记录（用于成绩曲线）
```

**设计特点**：逻辑与界面**未分离**——速度表更新、积分计算、出题调度等算法都直接写在主窗体的方法里，通过内存偏移（`[self+偏移]`）访问窗体字段。这给逆向带来了特征，也说明原作者是以"快速可用"为优先。

### 2.3 与原版对应的关键内存布局

原版把全局状态存在窗体对象 `self` 的字段里，逆向时以偏移标识：

| 偏移（示意） | 含义 | 本项目对应 |
|--------------|------|------------|
| `[self+62064]` | 每级所需积分（=10） | `SpeedTracker::kScorePerLevel` |
| `[self+62070]` | 累计积分（只增不减） | `SpeedTracker::m_score` |
| `[self+62074]` | 每题答对得分 | `UnitSession::scoreForItem()` |
| `[self+…]` | 连对次数、等级、速度表等 | `SpeedTracker` / `ZbUnit::speedTable` |

## 3. 数据模型与文件格式

### 3.1 原版数据组织

原版的可变数据保存在程序目录下的若干文件中（部分为二进制/加密），核心是三类：

1. **题库**：单元（Lib）集合，每个单元含题目（字/词、编码、拆分、联想），存储在 `user0.dat`。
2. **用户档**：用户配置 + 单元进度 + 每题速度表 + 等级/积分/连对。原版支持 `user0 / user1 / …` 多用户。
3. **码表 `zmmb.en`**：字/词到编码的映射，用于题目的拆码与查码。

### 3.2 数据模型

```cpp
// 题目
struct ZbItem {
    QString charText;    // c = 字/词/字根（题目）
    QString code;        // m = 编码（可能为空，需查码表）
    QString split;       // s = 拆分说明
    QString associate;   // a = 联想记忆提示
};

// 单元
struct ZbUnit {
    QString libName;     // 单元名
    int libNo;           // 单元编号（决定分类与算法分支）
    int count;           // 题目数
    int wrongCount;      // 累计答错
    int rightCount;      // 累计答对
    int used;            // 是否已完成
    QList<ZbItem> items;
    QList<int> speedTable;  // ★ 每题速度值（ms），核心状态
};

// 模式状态（训练 / 测试 各一份）
struct ZbModeState {
    QString libName;
    int grade, streak, wrongCount, rightCount;
    long long xp;        // 累计积分
    int totalTime, time, roundCount;
};
```

### 3.3 数据文件加密

原版 `user0.dat` 等文件并非明文，而是采用了典型的**自定义加密**：以某个种子做**线性同余发生器（LCG）**生成密钥流，再与数据做 **XOR**。逆向时需先还原 LCG 参数与种子才能读出明文。本项目在还原算法后，将数据改存为**明文 UTF-8**以便维护。

### 3.4 单元体系（5 类）

原版把 40 余个单元按学习阶段分为 5 类，对应界面上的 5 个 Tab：

| 分类 | LibNo 范围 | 说明 |
|------|-----------|------|
| 字根单元 | `0`、`2`、`10~19` | 笔画、主根、副根、全部字根 |
| 简码单元 | `20~34` | 一级/二级/三级简码及组合 |
| 词汇单元 | `50~53` | 二字/三字/四字/多字词 |
| 常用单元 | `100~105` | 常用字/词、冠军字、核心字词 |
| 提速单元 | `200~207` | 按基根数分类的字词 |

**设计意图**：编号不仅是索引，还承担**算法分支依据**——例如"提速单元"（`libNo ≥ 200`）在每轮题数、积分规则上都与普通单元不同（见第 4 节）。

## 4. 核心算法与公式

### 4.1 答案判定

原版把输入和正确编码都用空格包裹，再做**子串包含**判断，从而支持"多个编码任选其一"。等价逻辑：

```
输入包裹 = " " + trim(用户输入) + " "
for each 编码 in 正确编码列表:
    编码包裹 = " " + trim(编码) + " "
    if 编码包裹 包含 输入包裹 (忽略大小写):
        return true
return false
```

- 用空格包裹可避免 `"a"` 误匹配 `"avai"`（`" a "` 不会作为独立片段出现在 `" avai "` 中）。
- 相关常量：`kErrorMark = 50002`（错题标记，大于任何正常反应时间）；`kMaxElapsedMs = 20000`（超过 20s 视为离开，更新速度表时忽略）。

### 4.2 速度表更新

速度表是教学算法的核心状态，记录每题反应时间。规则：

```
若 elapsedMs >= 20000:           # 离开太久，忽略
    不更新
否则:
    若答对:
        if table[idx] >= 50000: table[idx] -= 1     # 错误标记"复活"
        if table[idx] < 50000:
            factor = 按码长的折算系数
            table[idx] = round(elapsedMs × factor)
    否则（答错）:
        table[idx] = 50002                            # 错误标记，下轮必中
```

**按码长折算系数**（对应原版 `sub_0040D3A6 ~ sub_0040D3ED`）：

| 编码长度 | 折算系数 `factor` |
|:--------:|:-----------------:|
| 2 码 | 0.7 |
| 3 码 | 0.5 |
| 4 码 | 0.3 |
| 其他 | 1.0 |

$$
\text{table}[idx] = \big\lceil \text{elapsedMs} \times factor \big\rfloor
\quad\text{（四舍五入取整）}
$$

**设计意图**：短码（2~4 码）在真实打字中应"秒反应"，因此用小于 1 的系数把其反应时间折算得更短，使短码题目更容易被判为"已熟练"，避免用户因短码题目反应慢而反复重练。

### 4.3 末位排序 + 洗牌

设题目总数 $N$，本轮题数 $n = \min(N, roundCount)$。

**步骤 1：索引初始化** $\text{index}[i] = i$。

**步骤 2：按速度降序（慢→快）局部排序**（原版为冒泡，每轮把最慢的冒到最前）：

$$
\text{index}[0..n-1] = \underset{\text{按 speedTable 降序}}{\text{partial\_sort}}(N, n)
$$

**步骤 3：Fisher-Yates 洗牌（仅前 $n$ 个）**。原版随机式（逆向还原）：

$$
v57 = (n + \text{Random}(401512 - n)) \bmod 401476
$$

然后 `swap(IndexArray[n], IndexArray[v57])`。其中 `401512 / 401476` 是与题库规模相关的常量，本质上等价于在剩余范围内取随机目标后对 $N$ 取模。

**出题**：依次取 `index[0], index[1], …`；本轮指针到 `roundCount-1` 即本轮结束。

### 4.4 每轮题数

**训练模式**（对应原版 `sub_411B58`）：

$$
\text{roundCount} =
\begin{cases}
\text{count}, & \text{libNo} \ge 200 \text{ 且 } count < 15 \text{（例外分支）}\\
\lfloor count/2 \rfloor, & \text{libNo}<200,\ count < 100\\
\lfloor count/3 \rfloor, & \text{libNo}<200,\ 100 \le count < 300\\
\lfloor count/4 \rfloor, & \text{libNo}<200,\ 300 \le count < 500\\
200, & \text{libNo}<200,\ count \ge 500\\
50, & \text{libNo} \ge 200 \text{（提速单元）}
\end{cases}
$$

**设计意图**：题目越多，单轮抽取比例越小（1/2 → 1/3 → 1/4 → 固定 200），保证单轮耗时可控；提速单元固定 50 题，便于量化提速成绩。

**测试模式**：

$$
\text{roundCount} =
\begin{cases}
2 \times count, & count < 50\\
count, & 50 \le count < 400\\
300, & count \ge 400
\end{cases}
$$

### 4.5 速度计算

**平均速度（字/分钟）**：

$$
\text{speed} = \left\lfloor \frac{60000 \times \text{charCount}}{\text{totalMs}} \right\rfloor
$$

**最近速度（最近 20 题窗口，手感更稳定）**：

$$
\text{recentSpeed} = \left\lfloor \frac{60000 \times \text{winKeys}}{\text{winMs}} \right\rfloor
$$

**击键速度（键/秒）**：$\text{hitSpeed} = \dfrac{1000 \times \text{keyStrokes}}{\text{totalMs}}$，成绩曲线中通常 ×10 放大显示。

### 4.6 有效计时 vs 秒表计时

- **训练（有效计时）**：两次输入间隔超过 `5000ms` 时，仅按 5000ms 计入——

$$
\text{countedMs} = \min(\text{elapsedMs},\ 5000)
$$

- **测试（秒表计时）**：$\text{countedMs} = \text{elapsedMs}$（无条件累计）。

**设计意图**：训练时用户中途离开（接电话、思考）不应计入，否则速度被严重拉低；测试则要真实反映"实际用时"。

### 4.7 等级与积分

- 每题答对得分（原版 `[self+62074]`）：

$$
\text{points} = \begin{cases} 3, & \text{libNo} < 20\\ 1, & \text{libNo} \ge 20 \end{cases}
$$

- 累计积分（原版 `[self+62070]`）**只增不减**，等级由其派生（原版 `grade = score / 10 + 1`，`[self+62064] = 10`）：

$$
\text{grade} = \left\lfloor \frac{\text{score}}{10} \right\rfloor + 1
$$

**设计意图**：字根单元（`libNo < 20`）每题给 3 分，因为字根是基础、更重要；且积分只增不减、等级不倒退，给学习者正向激励。

### 4.8 测试成绩

$$
\text{score} = \text{speed} - \text{wrongCount}
$$

即"平均速度减去错误数"，可为负，最高等于平均速度。

### 4.9 单元完成判定

设速度表中非零项个数为 $T$，题目总数为 $N$：

$$
\text{Used} = 1 \iff T \ge N
$$

即**每道题都至少被练过（速度值非零）**，该单元才算完成。

## 5. 关键函数与内存布局

下表汇总逆向得到的关键函数及与原版行为的对应关系（地址为逆向标识，非绝对运行地址）：

| 逆向标识 | 作用 | 行为说明 |
|----------|------|----------|
| `sub_411B58` | 计算每轮题数 | 按 `libNo` 与单元题目数决定 `roundCount`（见 4.4） |
| `sub_0040D3A6`~`D3ED` | 按码长折算耗时 | 2/3/4 码分别 ×0.7/×0.5/×0.3（见 4.2） |
| 出题排序 | 末位排序 | 按 `speedTable` 降序局部冒泡 |
| 洗牌 | Fisher-Yates | `v57 = (n + Random(401512 - n)) % 401476` |
| 判定 | 编码匹配 | 空格包裹 + 包含判定 |
| `[self+62064]` | 每级积分 | = 10 |
| `[self+62070]` | 累计积分 | 答对时 += `[self+62074]`，只增不减 |
| `[self+62074]` | 每题得分 | `libNo<20` → 3，否则 1 |
| 错题标记 | 速度表特值 | `50002` |
| 超时阈值 | 反应时间上限 | `20000 ms` |

**内存布局特点**：原版采用"窗体对象 + 偏移字段"的组织方式，所有运行时状态（速度表、积分、等级、连对等）都挂在主窗体上，算法方法直接读写这些偏移。逆向时这些偏移是最稳定的锚点。

## 6. 运行流程还原

### 6.1 启动

```
WinMain / FormCreate
 ├─ 读取注册表配置（显示方式、训练参数、热键等）
 ├─ 读取题库（单元/题目）
 ├─ 读取用户档（user0…）→ 恢复 进度 / 速度表 / 等级 / 积分 / 连对
 ├─ 加载码表 zmmb.en、字根字体 zmzg.ttf
 ├─ 恢复上次单元与模式（若已完成则跳下一个未完成单元）
 └─ 单元初始化：计算 roundCount → 初始化速度表 → 构建题目池 → 出第一题
```

### 6.2 训练模式一轮

```
出题（池中当前题） → 用户输入 → 回车/空格提交
   └─ 判定：
        ├─ 正确 → 更新速度表（折算耗时）、累计时间/字词/击键、连对+1、
        │           累计积分 += 每题得分
        │           本轮未结束 → 取下一题
        │           本轮结束   → 若还有轮次：重排+洗牌进入下一轮
        │                        否则：训练结束弹窗（测试/下一单元/继续/关闭）
        └─ 错误 → 显示正确编码、速度表打错题标记、连对清零、等待重试
```

### 6.3 测试模式

```
进入测试 → 切换秒表计时 → 取末位排序后的测试题 → 分页展示
   ├─ 答对 → 标记正确
   ├─ 答错 → 标记错误 + 回写速度表（加重）
   └─ 一页跑完 → 错题重测，直到全通过
结算 → 计算 speed / accuracy / score → 写入测试记录 → 绘制成绩曲线
```

## 7. 原版设计的取舍与局限

### 7.1 设计取舍

- **算法与界面耦合**：为快速开发，算法直接写在主窗体方法中。优点是实现简单、运行高效；缺点是难以复用、难以测试。
- **自定义加密存档**：`user0.dat` 等采用 LCG + XOR，防止用户随意篡改进度；代价是数据不可读、迁移困难。
- **单机单用户**（多档案 `user0/user1…`）：适合个人学习，无网络、无同步需求。
- **积分只增不减 + 等级派生**：避免"换单元/重开清空等级"，等级不会倒退，保护学习积极性。
- **有效计时保护**：训练离开（>5s）不计时，防止挂机刷速度。
- **码长折算系数**：短码题目反应时间折算得更短，使短码更易被判定为熟练，避免反复重练。

### 7.2 原版的局限

| 局限 | 说明 |
|------|------|
| 平台 | 仅 Windows（依赖 VCL / Win32） |
| 数据 | 二进制 + 自定义加密，不便维护与迁移 |
| 帮助系统 | RichEdit，仅 Windows 可用 |
| 图表 | TeeChart，绑定 Borland 生态 |
| 扩展性 | 算法与界面耦合，功能扩展需改动主窗体 |
| 命名风格 | 逆向代码多使用 `sub_xxxx` 风格，缺乏语义 |

### 7.3 对复刻的启示

逆向分析表明，原版的**教学价值几乎全部集中在算法层**（末位训练、速度表、折算系数、积分等级），而**界面层是附带产物**。因此复刻时应：

- **算法层忠实还原**：速度表更新、末位排序、每轮题数、积分规则必须等价。
- **界面层与数据层现代化**：用跨平台框架替换 VCL，用明文 UTF-8 替换加密二进制，便于维护与扩展。
- **保留"设计意图"**：如短码折算、有效计时、积分只增不减等，这些是教学效果的来源，不应在复刻中丢失。
